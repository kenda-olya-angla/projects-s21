## Exercise 00 — Диаграмма потоков данных (DFD, уровень 0)
**Что делать:** Для каждой задачи (барбершоп и доставка) нарисовать DFD уровня 0. На диаграмме показать:
- внешние сущности (кто взаимодействует с системой) — прямоугольники
- процессы (действия над данными) — овалы, с номерами и названиями "глагол + объект"
- хранилища данных (где что лежит) — две параллельные линии
- потоки данных (что передаётся) — стрелки с подписями

**Важные правила:** Процессы общаются друг с другом только через хранилища, а не напрямую. Диаграмма не показывает последовательность действий. Всё должно быть читаемо.

**Зачем:** Показать, как данные движутся внутри системы и между системой и внешним миром. Это помогает проверить, все ли нужные данные входят/выходят и используются ли они.

## Exercise 01 — Диаграмма "Плавательные дорожки" (Swimlane)
**Что делать:** Для каждой задачи нарисовать swimlane-диаграмму. Разделить на дорожки по ролям (кто участвует). На дорожках в виде прямоугольников показать шаги процесса в порядке выполнения. Стрелками — переходы между шагами. Ромбами — точки принятия решений (с вариантами на стрелках). Кружками — начало и конец процесса.

**Зачем:** Показать последовательность действий бизнес-процесса, кто за что отвечает и как роли взаимодействуют. Это помогает проверить полноту ролевой модели.

## Exercise 02 — Дополнение Swimlane артефактами
**Что делать:** Взять диаграмму из упражнения 01 и дополнить её. Для каждой роли добавить артефакты (документы, отчёты, заявки, коды, ошибки), которые эта роль создаёт или изменяет. Артефакты показать на дорожке рядом с действием. Пунктирной линией связать артефакт с действием, где он создаётся. Можно группировать несколько артефактов в один блок.

**Зачем:** Показать, какие именно документы и объекты порождает каждый шаг процесса. Это помогает понять, какая информация создаётся, изменяется или передаётся между ролями.

## Exercise 03 — Диаграмма состояний
**Что делать:** Для каждой задачи выбрать объект (сущность), у которого есть жизненный цикл. В задаче про барбершоп — нельзя брать "Заявку на услугу" (она в примере). Нарисовать диаграмму состояний: кружок начала, состояния объекта (прямоугольники с закруглёнными углами), стрелки переходов. На каждой стрелке подписать: событие (действие, которое переводит объект) и кто его инициирует. Если есть развилки — указать условия. Кружок окончания.

**Зачем:** Показать, как объект меняет свои состояния под влиянием событий. Это помогает понять поведение системы и не пропустить важные переходы.

## Exercise 04 — Таблица состояний
**Что делать:** Для каждой задачи выбрать объекты с жизненным циклом (те, для которых не строили полную диаграмму). Сделать таблицу, где каждая строка описывает один переход: предыдущее состояние → событие (действие) → следующее состояние. Указать инициатора события. Если есть условия — тоже указать. Отметить начало и конец жизненного цикла.

**Зачем:** Тот же смысл, что у диаграммы состояний, но в табличном виде. Для некоторых объектов и команд таблица удобнее и нагляднее.
