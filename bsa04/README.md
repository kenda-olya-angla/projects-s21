## Exercise 00 — Выявление сущностей
**Что делать:** Для каждой задачи (барбершоп и доставка) найти в тексте не менее 7 сущностей — то, с чем работает система. Сущности — это объекты реального или виртуального мира (клиент, заказ, услуга, мастер и т.д.). Для каждой сущности определить: название, назначение (зачем она нужна) и основные атрибуты (свойства, например, у клиента — имя, телефон).

**Как искать:** В тексте выделять пары "существительное — глагол". Если над чем-то выполняют действия и это встречается несколько раз — это кандидат в сущности.

**Зачем:** Понять, из каких "кирпичиков" состоит предметная область. Сущности — это то, данные о чём система будет хранить и обрабатывать.

## Exercise 01 — Проверка по CRUD
**Что делать:** Для задачи про барбершоп взять каждую сущность и проверить, кто и когда её:
- **C**reate (создаёт)
- **R**ead (читает/просматривает)
- **U**pdate (обновляет/изменяет)
- **D**elete (удаляет)

Заполнить таблицу: сущность → роль → действие. Если из задачи непонятно — выдвинуть гипотезу или отметить как "требует уточнения".

**Зачем:** Убедиться, что для каждой сущности определены все нужные операции. Если какая-то операция не нужна (например, удаление запрещено) — это осознанное решение, а не пробел.

## Exercise 02 — Словарь данных
**Что делать:** Для каждой задачи создать словарь данных. Для каждой сущности указать:
- название сущности
- мнемоника (короткое техническое имя)
- описание (бизнес-смысл)
- тип данных (строка, число, дата и т.п.)
- обязательность (можно ли оставить пустым)

**Чем отличается от глоссария:** Глоссарий объясняет термины на бизнес-языке. Словарь данных добавляет технические детали: тип данных, формат, ограничения.

**Зачем:** Чтобы разработчики точно знали, какого рода данные и в каком формате ожидает система.

## Exercise 03 — Логическая модель данных (ER-диаграмма)
**Что делать:** Для каждой задачи нарисовать ER-диаграмму (сущности и связи между ними). На диаграмме показать:
- все сущности
- атрибуты (ключевые свойства)
- связи между сущностями с указанием множественности (1:1, 1:М, М:М)
- для связей М:М добавить развязочную таблицу
- подписать связи глаголами (например, "Клиент → записывается на → Услугу")

**Зачем:** Визуализировать, как сущности связаны друг с другом. Это основа для проектирования базы данных и понимания логики системы.
