## Exercise 00 — Пользовательские истории для менеджера
**Что делать:** Для задачи про барбершоп взять роль **менеджера**. Найти минимум 2 его потребности в системе. Для каждой потребности написать пользовательскую историю (US) по шаблону: **"Как [роль] я хочу [действие], чтобы [получить выгоду]"**. Для одной US написать **критерии приёмки** (Given-When-Then). Для второй US написать **тестовый сценарий** (предусловия, действия, ожидаемый результат).

**Зачем:** Научиться кратко и понятно описывать ценность для конкретного пользователя. Критерии приёмки и тестовые сценарии помогают понять, когда история сделана правильно.

## Exercise 01 — Пользовательские истории для других ролей
**Что делать:** В задаче про барбершоп выбрать **две другие роли** (не менеджера). Для каждой роли найти минимум 2 потребности. Написать для каждой потребности US. Для каждой роли: по одной US снабдить критериями приёмки, по другой — тестовым сценарием.

**Зачем:** Покрыть потребности разных пользователей системы. Убедиться, что каждая роль получает свою ценность.

## Exercise 02 — Согласование пользовательских историй
**Что делать:** Найти сокурсников или друзей, чтобы они сыграли роли "пользователь", "заказчик", "разработчик". Обсудить с ними все написанные US. Проверить каждую историю по принципу **3С**:
- **Card** — помещается на одной карточке (не слишком длинная)
- **Conversation** — обсудили с разными ролями
- **Confirmation** — все согласовали

Проверить по критериям **INVEST**:
- **Independent** — независимость (если зависит — указать от какой)
- **Negotiable** — обсуждаемость
- **Valuable** — ценность понятна

Написать **протокол обсуждения**: кто участвовал, какие роли играл, какие изменения внесены в US и почему.

**Зачем:** US — не просто запись "для себя". Она должна быть согласована с командой и заказчиком. Обсуждение выявляет недопонимание и неточности. Протокол фиксирует, что изменилось и почему.
