## Exercise 00 — Назначение тегов первого уровня WSDL
**Что делать:** Взять WSDL-документы из задачи 4 (member.wsdl и pet.wsdl). Выписать логические части документа (теги первого уровня), кроме `<binding>`. Для каждой части указать одной фразой, для чего она нужна. Представить в виде таблицы.

**Пример:** `<types>` — описывает структуры данных, используемые в сообщениях. `<portType>` — описывает операции, которые предоставляет сервис.

**Зачем:** Научиться читать WSDL-документ — формальное описание веб-сервиса. Понимать, из каких разделов он состоит и за что каждый отвечает.

## Exercise 02 — Раздел `<schema>`
**Что делать:** На основе раздела `<schema>` в WSDL (где описаны типы данных) определить назначение ключевых элементов и атрибутов:
- `<element>` — что означает
- атрибут `type` — зачем нужен
- `<complexType>` — что означает
- `minOccurs` — зачем нужен
- `maxOccurs` — зачем нужен
- `<sequence>` — что означает
- что означает, если `minOccurs` или `maxOccurs` не указаны
- что означает `maxOccurs="unbounded"`
- как определить, обязателен ли элемент в XML-сообщении

Ответить одной фразой на каждый пункт. Результаты в таблице.

**Зачем:** WSDL использует XSD (язык описания структуры XML) для описания данных. Нужно понимать базовые элементы, чтобы читать спецификации.

## Exercise 03 — Обратное проектирование (по WSDL в требования)
**Что делать:** Для задачи 4 (Клуб любителей животных) выполнить обратное проектирование — по готовому WSDL описать требования к разработке. Взять 4 операции: `addMember`, `addPet`, `updatePet`, `getAllMembers`. Для каждой операции описать входное и выходное сообщение в виде таблицы: номер, имя операции, назначение, тип (простой: string/int/decimal), массив (да/нет), обязательность, примечание. Комплексные типы не указывать.

**Пример для addMember:**
- Вход: имя (string, обязательно), телефон (string, опционально)
- Выход: ID участника (int)

**Зачем:** Уметь читать WSDL как спецификацию требований и преобразовывать её в понятный для разработчиков и аналитиков вид.

## Exercise 04 — Обратное проектирование, дополнение
**Что делать:** Взять операции `getAllMembers` и `getMemberByName` из WSDL. Сравнить их выходные сообщения. Определить одной фразой, чем они отличаются.

**Пример ответа:** "getAllMembers возвращает список всех участников, а getMemberByName возвращает данные только одного участника по указанному имени."

**Зачем:** Понять разницу между похожими операциями, чтобы правильно их использовать при интеграции.

## Exercise 05 — Определение endpoint
**Что делать:** В WSDL-документах найти адрес (endpoint) веб-сервиса — URL, по которому сервис доступен. Для сервиса member и для сервиса pet выписать endpoint. Представить в таблице.

**Пример:** Сервис member — `http://example.com/soap/member`. Сервис pet — `http://example.com/soap/pet`.

**Зачем:** Чтобы вызвать веб-сервис, нужно знать, куда отправлять запросы. Endpoint — это сетевой адрес сервиса.
