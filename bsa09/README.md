## Exercise 00 — Класс «Персоны»
**Что делать:** Описать класс «Персоны» (общая информация о любом человеке в системе). Указать назначение класса (зачем он нужен). Выделить атрибуты: идентификатор, логин/пароль, имя, номер телефона, дата регистрации. Для каждого атрибута указать: название, тип данных, длину (если текст), обязательность (можно ли оставить пустым), значение по умолчанию, комментарии.

**Зачем:** Создать общий шаблон для всех людей в системе (клиенты, мастера, менеджеры), чтобы не повторять одни и те же поля в каждом классе.

## Exercise 01 — Классы «Клиенты» и «Сотрудники»
**Что делать:** Описать сущности «Клиенты» и «Сотрудники». Каждая — это наследник или связанная таблица с «Персонами». Указать назначение каждой сущности. Атрибуты: свой идентификатор (первичный ключ), ссылку на «Персоны» (внешний ключ), дату регистрации. Для атрибутов — тип, длина, обязательность, значение по умолчанию, комментарии.

**Зачем:** Разделить людей на роли (клиенты отдельно, сотрудники отдельно), добавить уникальные для каждой группы поля (например, у сотрудников может быть должность, у клиентов — история записей).

## Exercise 02 — Сущности-справочники
**Что делать:** Описать три справочные сущности, которые нужны для реализации UC01, UC02, UC03:
- **Роли сотрудника** (кто мастер, кто менеджер)
- **Услуги** (список услуг: стрижка, покраска и т.д.)
- **Услуги мастера** (какие услуги какой мастер оказывает)

Для каждой: назначение, атрибуты (идентификаторы, ссылки на сотрудников и услуги, название роли/услуги). Спецификация атрибутов как в предыдущих упражнениях.

**Зачем:** Справочники нужны, чтобы заполнять выпадающие списки и связывать сущности между собой. Например, без справочника «Услуги» нельзя будет выбрать услугу при бронировании.

## Exercise 03 — Сущность «Слоты обслуживания»

Назначение: фиксировать дату, время начала, к какому мастеру привязан слот, какой клиент забронировал. Атрибуты: идентификатор, дата, время начала, мастер (ссылка на Сотрудники), клиент (ссылка на Клиенты). Полная спецификация атрибутов.

**Зачем:** Это центральная сущность для записи клиентов. Слот связывает мастера, клиента и время оказания услуги.
